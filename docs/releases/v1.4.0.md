# Progressive Tracker v1.4.0 — límites de nivel manuales

**Paquete portable para Windows x64.**
Base funcional: `master`, commit `8032d537f81df031c1f5d1aed72a1196170e2b02`, que incorpora los PR #22, #23 y #24 sobre v1.3.0. Sobre esa base solo cambian la versión y sus documentos; no hay funciones adicionales ni refactorizaciones.

## Novedades

### Límites de nivel manuales por partida y juego

Tú defines las etapas de tu aventura (por ejemplo «Primer gimnasio», Nv. 20) y el Tracker te avisa cuando un Pokémon del equipo supera el límite vigente. Los avisos son informativos: no impiden subir de nivel ni cambian nada en la partida. El Tracker **no incluye límites oficiales ni predeterminados** de ningún juego, romhack o desafío, y no los deduce de la memoria.

- **Sección Progreso**: etapa vigente con su límite, «Etapa N de M» y barra de avance; botones para etapa anterior y siguiente; selector de etapa vigente (o ninguna); casilla para mostrar u ocultar el límite; y el equipo comparado con el límite.
- **Indicadores**: un chip «Límite Nv. N · etapa» en la cabecera (con «· X por encima» si algún Pokémon lo supera) y «+N sobre el límite» en las fichas del equipo. Los huevos no cuentan. No aparecen si la partida no tiene etapas o si ocultas los límites.
- **Editor de etapas**: añade, renombra, cambia el nivel, reordena y elimina. Los cambios son un borrador hasta pulsar «Guardar cambios»; «Descartar» los deja como estaban. Cada error aparece junto a su fila. Un límite menor que el de la etapa anterior se avisa, pero se puede guardar. Cambiar de sección conserva el borrador; cambiar de partida, recargar o cerrar con cambios sin guardar pide confirmación.
- **Reglas**: hasta 64 etapas, nombres de 1 a 60 caracteres, límites enteros de 1 a 100. Al eliminar la etapa vigente la partida queda «Sin etapa vigente» y debes elegir otra de forma explícita.
- Cada partida y cada juego guardan sus propias etapas, de forma independiente.

### Listas de etapas reutilizables

Al final de Progreso, **Exportar lista…** guarda tus etapas en un archivo JSON (`limites-de-nivel.json`) para reutilizarlas en otra partida o compartirlas, e **Importar lista…** carga uno.

- El archivo contiene solo `format`, `version` y `stages` (nombre y límite, en orden). No incluye la etapa vigente, la opción de mostrar, muertes, encuentros, nombres de partida, claves ni rutas de tu equipo; es seguro compartirlo.
- Al importar se muestra una **vista previa** (nombres, límites, orden y avisos) sin cambiar nada. Si la partida ya tiene etapas, debes confirmar el reemplazo de forma explícita; la lista se reemplaza entera, no se mezcla. No se elige ninguna etapa vigente.
- Los archivos inválidos (JSON dañado, versión de formato más nueva, campos desconocidos, límites fuera de rango, más de 64 etapas o más de 32 KB) se rechazan con un mensaje claro y sin cambiar tu lista.
- Con cambios sin guardar en el editor, importar queda desactivado para no descartarlos en silencio.

## Actualizar conservando partidas

1. Cierra las ventanas del Tracker y respalda `%LOCALAPPDATA%\PokemonTracker\runtime`.
2. Extrae el ZIP en una carpeta nueva. Mantén tu carpeta `sprites_personalizados` si la utilizas.
3. Ejecuta `PokemonTracker.exe`. La ubicación de partidas, perfiles, CSV, Soul Link, datos de Definitive Randomizer y configuración OBS no cambia desde v1.3.0.
4. No reemplaces ni borres la carpeta de datos para actualizar. Las partidas de v1.3.0 se abren sin cambios: sin etapas configuradas, su archivo de progreso no se modifica. Si necesitas regresar a v1.3.0, conserva el respaldo previo; el bloque de límites de una partida que los use se conserva sin alteraciones y v1.3.0 lo ignora.

El paquete es portable y requiere Windows 10/11 x64 y Microsoft Edge WebView2 Runtime. No requiere instalar Python ni Node.js.

## Compatibilidad y límites

- Soul Link, las fuentes de OBS, la lectura de memoria y el formato Definitive Game Data v1 no cambian: los límites no se envían al compañero, no se leen de la RAM y no viajan en DGD. La copia «Guardar sesión…» incluye los límites dentro del progreso.
- No hay capa de OBS para los límites en esta versión.
- Los límites los escribes tú; el Tracker no sabe qué límite «corresponde» a una etapa de un juego o de un romhack.
- Se conserva la compatibilidad anunciada de v1.3.0 y sus límites por emulador/revisión, reinicios Gen6, ROM hacks, escenas OBS y combates especiales.
- Comprueba el SHA-256 de lo que descargues con `SHA256SUMS.txt`. Si el EXE no lleva firma Authenticode válida, Windows SmartScreen puede avisar; este documento no afirma que esté firmado.
