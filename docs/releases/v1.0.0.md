# Progressive Tracker v1.0.0 — objetos en OBS, Soul Link más seguro y registro de diagnóstico

Primera versión estable. Muestra los objetos equipados en OBS, corrige el sprite en blanco y negro de los Pokémon caídos y refuerza la seguridad, el guardado y la sincronización Soul Link.

## Descarga

Descarga **PokemonTracker-Windows-x64.zip**, extráelo y abre **PokemonTracker.exe**. También se ofrece el EXE por separado. Windows 10/11 de 64 bits y Microsoft Edge WebView2 Runtime; no hace falta instalar Python ni Node.js.

Antes de actualizar, cierra el tracker y respalda `%LOCALAPPDATA%\PokemonTracker\runtime`. Las ROM y los guardados del emulador se conservan. El paquete incluye únicamente el ejecutable, la licencia y la guía; no contiene perfiles ni credenciales privadas.

## Novedades

- **Objetos equipados en OBS:** nueva capa «Objetos» como fuente independiente (`layer=items`) o dentro de la composición, debajo de los motes. Se puede mostrar el nombre, el icono o ambos, con tamaño y color propios. Los iconos se descargan una vez y quedan guardados; si un icono no está disponible se muestra el nombre.
- **Registro de diagnóstico:** `%LOCALAPPDATA%\PokemonTracker\logs` guarda conexiones, muertes, avisos de guardado y errores de sprites o de Soul Link. «Guardar diagnóstico» incluye las últimas líneas. Tokens, invitaciones y claves se ocultan antes de escribirse.
- **Avisos visibles:** si no se puede guardar el progreso o un comando se rechaza (por ejemplo, marcar dos veces la misma muerte), la interfaz lo indica sin confundirlo con un problema de conexión.
- **Modo demo completo:** la demo genera sprites para probar el overlay sin emulador y ya no usa las credenciales de Soul Link de la partida.

## Correcciones

- El sprite de un Pokémon caído vuelve a mostrarse en blanco y negro en OBS, también con sprites animados o personalizados, y recupera el color al revivirlo.
- Un sprite que no se puede convertir ya no congela el resto de posiciones del overlay.
- El overlay no acumula peticiones cuando el tracker tarda en responder y la barra de PS no retrocede.
- La compartición de OBS por VPN se mantiene al cambiar de partida y conserva su puerto.
- La vista del compañero usa las rutas de su propio juego.
- Un archivo de progreso dañado ya no impide abrir la aplicación: se aparta, se restaura la copia `.bak` y se avisa. El guardado se fuerza a disco y una muerte no se pierde si falla una escritura.
- La lectura de memoria sigue funcionando aunque `state.json` esté bloqueado por OneDrive o un antivirus.
- La versión mostrada en la aplicación coincide con la publicada.

## Seguridad

- Los datos del compañero de Soul Link se validan al enviarlos y al recibirlos, y todo lo que se muestra en la interfaz se escapa. Un valor inesperado se limpia o se descarta sin detener la sincronización.
- Las páginas del tracker envían una política de contenido que bloquea scripts insertados.
- El servidor local cierra conexiones inactivas y no descarga sprites a petición de sitios externos.
- Las dependencias de la compilación están fijadas con hashes.

## Validación y límites

Pruebas automatizadas de Python (3.13 y 3.14), interfaz JavaScript y Worker, junto con análisis estático. El EXE portable pasa la comprobación de API, recursos y carga de Python.NET/WinForms con datos aislados, y se comprobó en WebView2 nativo y con una partida real. `SHA256SUMS.txt` permite verificar los archivos publicados.

El ejecutable todavía no está firmado digitalmente, por lo que Windows SmartScreen puede mostrar un aviso la primera vez. La lectura de memoria es experimental en Azahar/Citra y en escenas de combate especiales. La aplicación solo lee RAM; no altera la ROM ni el guardado.

El Worker oficial de Cloudflare ya está actualizado. Quienes usen su propio Worker deben actualizar también su código; no se necesita migración de D1.
