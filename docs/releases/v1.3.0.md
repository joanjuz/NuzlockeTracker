# Progressive Tracker v1.3.0 — datos del Randomizer por partida

**Candidato estable para Windows x64, pendiente de autorización de publicación.**
Base funcional: `master`, commit `69b4aa17753a4b23ffc3e1e604b421a281077f52`, que incorpora el PR #20 sobre v1.2.0. En esta preparación solo cambian la versión y sus documentos; no hay funciones adicionales ni refactorizaciones. No existe una etiqueta definitiva creada por esta preparación.

## Novedad

En **Conexión → Datos de Definitive Randomizer**, importa un JSON Definitive Game Data v1 exportado desde un proyecto guardado de Ultra Sol o Ultra Luna. Antes de aplicar se muestran el juego, los contadores y una muestra de diferencias. Puedes reemplazar o retirar los datos y cada partida conserva su propia importación entre sesiones.

El Tracker utiliza nombres, tipos, estadísticas base, habilidades informativas, propiedades de movimientos y evoluciones por especie/forma. Los datos DGD prevalecen sobre CSV y referencias cuando el juego coincide. Retirar DGD restaura las referencias/CSV. Las estadísticas calculadas, PS, IV/EV y habilidad actual siguen procediendo de RAM; el archivo no escribe en ROMs, guardados ni memoria.

## Actualizar conservando partidas

1. Cierra las ventanas del Tracker y respalda `%LOCALAPPDATA%\PokemonTracker\runtime`.
2. Extrae el ZIP candidato en una carpeta nueva. Mantén tu carpeta `sprites_personalizados` si la utilizas.
3. Ejecuta `PokemonTracker.exe`. La ubicación de partidas, perfiles, CSV, Soul Link y configuración OBS no cambia desde v1.2.0.
4. No reemplaces ni borres la carpeta de datos para actualizar. Si necesitas regresar a v1.2.0, conserva el respaldo previo.

El paquete es portable y requiere Windows 10/11 x64 y Microsoft Edge WebView2 Runtime. No requiere instalar Python ni Node.js.

## Compatibilidad y límites

- DGD v1 admite Ultra Sol/Ultra Luna; no añade lectura de memoria DS, Switch, Sol/Luna ni revisiones nuevas.
- Si el exportador no acredita la revisión instalada, se presenta como desconocida y requiere confirmación. El fingerprint identifica datos exportados, no la ROM que corre el emulador.
- Efectos avanzados, descripciones y otros campos no exportados conservan la referencia. DGD no instala parches ni acredita su funcionamiento.
- La importación es local por partida; el documento no se comparte automáticamente por Soul Link. Cada jugador debe importar el suyo.
- Se conserva la compatibilidad anunciada de v1.2.0 y sus límites por emulador/revisión, reinicios Gen6, ROM hacks, escenas OBS y combates especiales.
- El candidato local no usa firma remota. Comprueba el estado Authenticode y SHA-256 del artefacto entregado; no se presenta como EXE firmado si no lo está.

## Validación y procedencia

Se reutiliza el CI aprobado del PR #20: Python 3.13/3.14, JavaScript, Worker, lint/tipos, E2E y paquete Windows. El propietario confirmó manualmente la integración DGD antes de esta preparación. La validación del paquete candidato y sus hashes se entregan por separado; no se atribuye al paquete una prueba en emulador no ejecutada.

`PROVENANCE.json` adjunto registra el commit definitivo y la correspondencia de las entradas empaquetadas con ese commit. `SHA256SUMS.txt` identifica ZIP y ejecutable. El ZIP no contiene ROMs, partidas, credenciales ni recursos privados.
